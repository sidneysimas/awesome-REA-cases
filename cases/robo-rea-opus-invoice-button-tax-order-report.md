# 发票按钮重建：Robo报告REA与Opus分层分析，并指出绿灯测试漏掉税序错误

分类：应用与客户端 · REA
记录日期：2026-10-21
阶段：待验证

2026年10月21日23:21:00（北京时间），Robo（@0xRoboAI）发布一段REA与Opus 5.5重建发票功能的报告。这是往期20:00至24:00窗口的待补审候选，不是本轮新发布的项目。目标不是复制整个收费软件，而是理解一款未命名、据称年费468美元的应用中一个发票按钮的行为，形成规格后另做实现。

原帖描述REA映射9,316个函数，Opus读取214个，再写SPEC.md并做50项测试。其工作分层为低推理强度处理180个函数、花费1.08美元，高强度处理31个、1.27美元，最高强度处理3个、1.14美元；作者声称总计3.49美元、145分钟，最初12分钟由使用者设定目标。这些是帖子给出的成本与时间，不是本合集计量；没有原始计费、工具轨迹或缓存日志来支持其扫描免费、缓存每百万token 0.20美元而非4美元等进一步价格说法，也不据此推导通用省费比例。

有阅读价值的限制是测试反例：原帖称首版50项全过，但其中一条规则仍错；把折扣移到税前，30个常规样例仍通过，10个边界样例中只有2个能检出。文字未解释这两组与全部50项的完整对应，也未给发票输入、税法辖区、原应用的正确税序或失败日志，不能据此判断应当税前还是税后折扣。作者另称多层混淆情形得分0%，但没有定义样本和评分；不泛化为所有保护或所有REA分析的成功率。
