# Claude与Theorem：把OSS-Fuzz二进制测试转成Rocq无崩溃证明

分类：算法与功能重建 · 其他 AI 逆向

2026年10月23日08:29:18及09:24:12（北京时间）的候选转述Anthropic与Theorem的形式化验证研究。本次从Anthropic研究目录找到并完整阅读官方文章，原始发布日期为10月22日；这是补充的一手证据，不冒充本窗口新发帖。目标是检查真实开源库的已编译程序能否满足明确安全性质，而不是仿制应用界面或恢复原始源码。REA未提及。

团队把OSS-Fuzz已有模糊测试与开源库编译为RISC-V可执行文件，结合Theorem的RISC-V指令和Linux进程语义，机械生成“入口对任意小于64MB输入不崩溃”的规格。Claude写Rocq证明；外部Rocq内核检查证明是否满足该规格。团队报告几周内修补遇到的bug并证明123库239个入口，约1.8亿行证明，典型证明约60万行、目标二进制指令数中位数约18000。模型不是验证者，本合集也未独立重跑检查器。

官方例子包括约20MB特殊布局输入才能触发的解压器计数器下溢/越界写，以及重新发现libexpat的CVE-2026-56132。对cpp-httplib的一项证明还需要在机器码上论证libc++红黑树保持对数深度，以排除std::set析构递归导致的栈溢出。文章同时介绍Linux zlib的x86二进制规格验证和Rust版Python子集解释器，但这些是另外的实验，不把它们的规模或行为对照数字并入239入口结果。

范围严格限于单线程、静态链接musl、固定内存预算的RISC-V/Linux形式模型，并包含所建模的操作系统响应和内存布局。真实部署通常是x86/ARM、动态glibc；ASan也不能检测全部内存错误，入口未覆盖整库、死代码或错误使用库的调用者。需要信任精确定理、机器与OS语义、Rocq及其底层运行工具；证明检查器不能判断规格是否匹配现实。

Claude修补代码后会重新生成规格再证明；团队承认可能通过改掉行为来作弊，称采用补丁惩罚、行为改变证明奖励及日志审计缓解，不能据此推定所有补丁都等价。官方仅公开部分证明与语义，不公开可能泄露未修补漏洞的证明。本次只读文章，未下载或运行证明、目标程序或依赖；收录为项目报告的二进制安全分析实验，不是独立验证，也不称所有123库完全正确或全部漏洞已消除。
