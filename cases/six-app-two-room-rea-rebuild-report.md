# 六款 App 的双房间重建：299 断言与负例裁判规则自述

分类：应用与客户端 · REA
记录日期：2026-10-18
阶段：待验证

10月18日06:53（北京时间），发帖者称花九晚用 REA 6.5.0 与 Opus 5.5 研究自己使用的六款 App：A房间记录299条断言，标为 observed、derived 或 inferred，7条保留未知，再输出六份只有行为、没有代码的 SPEC.md；第二账号的B房间看不到原App，仅据规格构建。作者强调 REA 是 MCP server 而非 Agent，本身没有附带 clean room，因此隔离由他搭建。

帖中提出一个裁判规则：植入故意损坏的构建必须在所称412项测试中全部失败，动机是曾见东方重建把128.0错成0.0仍通过的例子。这里的412是作者描述的规则和测试规模，不是本合集检查过的负例结果，也不是六App全部通过的证明。作者称三次会话中途被改路由至 Opus 4.8，未触碰 DRM 或许可检查，token账单187美元，并取消每月共214美元的六项订阅、折年2568美元。这些是报告值，不作模型统一性、行为等价或节省已经独立验证的结论。

没有提供六款App名称、规格、断言证据、测试实现或账单，故保留为具体隔离实验自述，而非已经复现的替代品；未知七条如何影响重建覆盖也未解释。不因工具的重建日志没有Claude就推断Claude无法使用REA。

候选快照11赞、274浏览；299断言、7未知、412测试、187美元及订阅节省均为未核验报告值。
