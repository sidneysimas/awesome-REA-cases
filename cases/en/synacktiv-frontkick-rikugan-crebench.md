# Frontkick vs Rikugan: a prompt confound in two cryptographic binary tasks

Category: Algorithms and feature recovery · Other AI-assisted work
Record date: 2026-10-18
Stage: Analysis test

At 00:17 Beijing time on October 18, 2026, @MalwareBibleJP discusses Synacktiv's Frontkick/Rikugan comparison. Supplementary reading checks Matthieu Breuil's October 13 original for experimental evidence; it is not a new publication inside the candidate window. The task is to identify algorithms and keys in stripped cryptographic binaries, reimplement decryption and retrieve a flag. The author selects AES-128-CBC and ChaCha20 from CREBench, using hardcode_plain and O0, with Claude 5.5 Sonnet, four runs per task per tool and a cumulative input/output budget of one million tokens. This is not a full-benchmark evaluation.

Rikugan uses predefined tools and argument validation. Frontkick executes generated code directly in Binary Ninja's Python environment without per-action schema validation. It supplies installed libraries and open-binary information in the initial prompt, truncates turns older than the latest four to 500 characters, compacts history at context saturation and retrieves project-validated Python recipes generated by Opus 5.5 after execution errors. The article acknowledges that frequent truncation harms prompt caching and plans improvements; it provides no Frontkick download location.

The article broadly claims about half the tokens and nearly triple the score. Computing from its eight-run table gives a total-token ratio of approximately 0.634 and mean scores of 85.9375/100 versus 31.25/100, not three times as many successful runs. Frontkick's first AES run still consumes 1,007,262 tokens and 42 turns for a zero score; six of Rikugan's eight runs exceed one million tokens, so the budget is not an unexceeded hard guarantee. Rikugan repeatedly tries the unavailable pycryptodome rather than installed cryptography, whereas Frontkick uses the latter with explicit library guidance. Synacktiv therefore does not establish intrinsic CodeAct superiority and recommends aligning library prompts before a rematch. These are the author's published experiments and this collection's table calculations, not independent reruns or guarantees for real software and other models.
