# Four REA comparisons: single-run OBS noise-gate, Android dungeon and payment-prompt experiments

Category: Algorithms and feature recovery · REA
Record date: 2026-10-21
Stage: Analysis test

At 07:30 Beijing time on October 21, 2026, varun bhardwaj (varunPbhardwaj) summarizes four experiments to distinguish REA tool integration from model ability: a small program, the real OBS noise gate, an Android dungeon game supplied only as a compiled app, and a payment script. The first three reportedly scored 20/20 with and without REA. The dungeon was reportedly graded against the real game; REA located code in two searches and the model caught three decompiler errors.

The payment task is not the same tool-on/off comparison: the same AI received two prompts, with one double-charging 400 orders and the other scoring 1,000/1,000. This does not establish a real merchant incident, and scores from different experimental conditions must not be pooled. The author reports 13–17% time/cost savings without changed outcomes and explicitly says each condition ran once: a case study, not a benchmark.

Retrieving both originals confirmed that the deferred October 20, 12:04 candidate is the same author's earlier 20/20/payment post. It is retained as historical evidence, not a new-window result. Game identity, sample builds, model version, itemized inputs/outputs, billing and logs were not obtained for recomputation. The report does not establish that REA is useless, models are generally equivalent or arbitrary tasks are recoverable. No samples were run here.
