# Link's Awakening: the Claude-assisted LASRecomp project

Category: Games and preservation · Other AI-assisted work
Record date: 2026-10-19
Stage: Needs verification

The earlier overview says Link's Awakening was recompiled to PC almost entirely with Claude Code. An October 15, 14:17 candidate adds the project name LASRecomp and the caveat that particular actions cause crashes. Reading peiikai/LASRecomp's public README then confirmed the target as the 2019 Switch version v1.0.0. The project describes static recompilation to native Windows, macOS and Linux applications. The author explicitly says almost all code, tooling, reverse engineering and documentation were done by Claude Code, with humans directing, testing and reviewing. That documentation describes a beta: macOS supports only Apple Silicon, Linux ARM is experimental and untested on actual hardware, and known crashes include inspecting a particular dresser and returning to the title screen. The project contains no game files, assets or fonts; users must lawfully provide the original game. This collection did not compile or run it, quantify AI's contribution or guarantee full behavioral equivalence. The existing ID and early source are preserved; public documentation was earlier retrospective supporting evidence.

A LEO open-source overview at 22:45 Beijing time on October 19 again describes LAS Recomp, claiming local recompilation at first launch, 21:9 support, key remapping, a built-in randomizer, MetalFX on macOS and Vulkan on Windows/Linux, with occasional black blocks in beta dungeons. It lists AVX2, Vulkan 1.3, clang, SDL 3 and Python 3.12 for self-building and mentions an iOS fork. These additions remain secondary descriptions, not a fresh check of the current repository or cross-platform testing here. Claimed stars, another video's engagement and display features are not stability acceptance tests.

October 15 secondary-account snapshot: 144 likes, 24,723 views and 16 reposts; earlier public README reading confirmed the project and AI claims, without independent execution.
A new October 15, 18:04 account claims a 60 FPS lock, internal rendering up to 4× and problems above 60 fps. Rereading the public README this review confirmed only adjustable internal rendering and beta/crash limitations, not 60 FPS or a 4× maximum. Exact figures remain secondhand rather than current cross-platform measurements.
