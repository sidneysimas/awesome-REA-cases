# 楼宇门铃实时画面：Mattia用REA与Ghidra研究固件，以树莓派替代室内屏

分类：硬件与设备互通 · REA
记录日期：2026-10-22
阶段：待验证

2026年10月22日21:37:29（北京时间），Mattia Righetti（@matttrighetti）报告用REA和Ghidra检查楼宇门口机的ARM固件，看到UDP收发路径及Call、CallAck、Accpet、HangUp、Tick等XML模板。Accpet沿用作者原文，不擅改为其他标识。目标是理解自家楼宇摄像门铃与室内对讲屏的通信，并让浏览器直接显示摄像画面。

补查同串根帖（10月21日20:47:05）及10月22日00:13:37的早期结果：作者称用树莓派GPIO连接已有UART root shell，并用Codex luna 5.6 medium制作显示门铃实时数据的网页。两条均早于本轮20:00至24:00，只用于明确背景、AI角色与早期结果，不计为本轮新候选。

同串10月22日21:35至21:53的后续说明称，作者观察室内屏与门口机的通信，通话时UDP/6600有12包；由固件细节解读加密消息后，确认与应用通话命令对应。他断开室内屏，将树莓派接到原以太网线，报告可建立并保持会话，再接收UDP组播视频。作者描述解码后是含序号、时间戳和帧边界标记的小头部及H.264数据，最终制作Rust服务，以FFmpeg将H.264包装成短HLS分段供浏览器实时查看，并附结果图片。本条只摘要互通研究及结果，不提供解密材料或攻击操作。

本次读到的是作者叙述，没有取得设备品牌型号、固件版本、仓库、抓包正文、源代码或延迟与稳定性测试，也未独立验证视频、接线与门禁安全。结果不能推广为所有楼宇门铃的通用方案，更不能视为已实现开门、双向音频或安全加固。REA、Ghidra与Codex角色均按作者归因，保留unverified。
