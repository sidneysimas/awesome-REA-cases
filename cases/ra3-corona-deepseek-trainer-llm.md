# 红警3与日冕：DeepSeek 重写旧修改器，并把 LLM 接入战局

分类：游戏与游戏保存 · 其他 AI 逆向
记录日期：2026-10-21
阶段：待验证

2026年10月21日20:12（北京时间），探姬（@ProbiusOfficial）描述用 dsv4.1f 研究《红色警戒3》与日冕 Mod。起因是自己长期使用2009年由 Cheat Engine（CE）生成的31项修改器，经常在游玩时崩溃，想把遭遇战的协议技能带进原版战役。作者说黑盒实验从v0到v26仍未实现空投随机单位；后来结合解包内容，才发现战役缺少对应技能释放资源，部分单位和折跃逻辑存在，但缺美术资源，部分特殊hash对象也不在。不能将最终修改器完成等同于这个最初目标成功。

作者随后让模型分析旧CE修改器并重写逻辑，称模型会把已被修改的目标汇编当成无效改动，擅自另改，需要每改一两处就人工打断。WorkBuddy又将猜测和不稳定黑盒记录写进记忆，模型对涉及随机函数的测试也常只跑一次。作者把迭代1017后问题约50%归于旧黑盒记录、40%归于不遵守测试流程；这是个人诊断，不是审计统计。清理猜测和不稳定记录后才有所改善。作者称运行态解包时恢复了Mod部分核心结构及调用游戏函数的方法，最终重写修改器并把LLM接入游戏内部函数以干预战局。

主要突破据称发生在干净Windows机器上，只用Python；此前曾用IDA无MCP导出部分内容，在主机上展示组件，也试过REA，但不能把成果归为REA独立完成。没有公开源码、补丁、随机测试日志或稳定性对照；更安全、更强大及完成接入均为作者自述，未独立运行，也不涉及线上反作弊绕过。
