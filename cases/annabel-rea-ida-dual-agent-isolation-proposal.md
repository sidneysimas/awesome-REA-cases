# REA/IDA双Agent隔离：规划者只接规格，专员保留原始分析的提案

分类：应用与客户端 · REA
记录日期：2026-10-29
阶段：待验证

2026年10月29日12:43:05（北京时间），Annabel（@annabel_2580）针对Claude执行REA任务时的上下文外泄风险提出双Agent方案：主规划者只接经过清理的结论，专门的分析Agent在本地、替代模型或独立工作区持有REA/IDA会话。她比较全流程本地开源模型与保留强规划模型的折中，并明确质疑/rename分流在真实逆向中是否仍会留下足以触发过滤的上下文。

同日13:13:42，@themegamind24提出相近设计：在独立git worktree里让本地模型或Kimi处理二进制，回传经过整理的逻辑规格。该帖称这会让主账号完全安全，但没有提供隔离测试、数据流审计、真实目标或封号对照，因此只补充架构思路，不采信安全保证。git worktree是文件工作区分离，不自动形成网络、权限或模型输入的空气隔离。

本窗口17:18:59与17:19:55，Cloud Whisperer（@joyfulframes）在另一个讨论串补充经验：称曾把IDA反编译片段交给主Claude账号后受限；即使分层，返回大量汇编或反编译特征仍可能触发云端审查。他又称试过本地开源模型配REA，认为复杂二进制推理明显较弱，常只能处理简单样本，并建议同类分层也可用于Ghidra与Binja。这些是个人经验，没有给模型、样本、版本或基准，不能推成所有本地模型的结论或证实限制原因。

补读该讨论的10月27日22:14:41父帖，确认实践哥Li（@MinLiBuilds）的Dario规划/Sam分析、worktree与精炼规格提案；它只是较早补充背景，不是本轮新候选，也不把Annabel或Cloud Whisperer说成该设计原创者。父帖夹带套餐推广并声称账号安全，未有验证，相关促销不作为证据。

这是工作流idea与风险经验集合，而非已完成的目标重建或安全隔离测试。平台风控因果没有独立证据，清理规格仍可能泄漏内容，服务条款与模型限制继续适用。本合集只核对作者与文本，没有部署架构、规避过滤、测试账号或运行样本。
