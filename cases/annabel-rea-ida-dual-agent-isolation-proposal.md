# REA/IDA双Agent隔离：规划者只接规格，专员保留原始分析的提案

分类：应用与客户端 · REA
记录日期：2026-10-29
阶段：待验证

2026年10月29日12:43:05（北京时间），Annabel（@annabel_2580）针对Claude执行REA任务时的上下文外泄风险提出双Agent方案：主规划者只接经过清理的结论，专门的分析Agent在本地、替代模型或独立工作区持有REA/IDA会话。她比较全流程本地开源模型与保留强规划模型的折中，并明确质疑/rename分流在真实逆向中是否仍会留下足以触发过滤的上下文。

同日13:13:42，@themegamind24提出相近设计：在独立git worktree里让本地模型或Kimi处理二进制，回传经过整理的逻辑规格。该帖称这会让主账号完全安全，但没有提供隔离测试、数据流审计、真实目标或封号对照，因此只补充架构思路，不采信安全保证。git worktree是文件工作区分离，不自动形成网络、权限或模型输入的空气隔离。

这是具体的逆向工作流idea，而非已完成的目标重建。两位作者对平台风控的因果解释没有独立证据；清理规格也可能泄漏内容，服务条款与模型限制仍适用。本合集补查确认作者及文本，未部署该架构、规避过滤或测试账号，不能把它当作绕过安全策略的可靠办法。
